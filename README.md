# glq-benchmarks

Provenance-tracked model-performance benchmark results, generated by
[**`glq-bench`**](https://github.com/cnygaard/glq) (ships with the `glq` package:
`pip install "glq[bench]"`).

This repo is the **durable, centralized store** for benchmark records — decoupled
from compute so numbers survive spot-instance churn. Each record is one
`(model × task × GPU)` measurement carrying the full provenance needed to reproduce
and compare it: exact serving command, torch/vLLM/transformers/sglang versions, GPU
model, **GPU memory at load**, **tokens/sec**, base/parent model, quant method, and
HF links.

## Contents
- **[`LEADERBOARD.md`](LEADERBOARD.md)** — auto-generated: the weighted **% -of-bf16
  quality index** across all bases, plus a per-base comparison table (every quant
  method vs that base's bf16). Regenerate with `glq-bench leaderboard`.
- **`records/<base_model>/<model>.jsonl`** — append-only JSONL, one `BenchRecord`
  per line. Keyed by base model so every quant (GLQ / NVFP4 / GPTQ / AWQ / bf16)
  of a base sits together and compares against the shared bf16 baseline.
- **`plots/`** — `index`, `quality_vs_bpw`, `pareto_quality_vs_vram`, `toks_by_gpu`.

## How quality is scored
`index(M) = Σ wₜ·(scoreₜ(M) / scoreₜ(bf16 of same base)) / Σ wₜ` over the
standardized quality tasks (perplexity inverts). bf16 = 100%. Throughput and
VRAM-at-load are reported **beside** the index, not folded in (they are
GPU-dependent). `n` = number of tasks averaged — a model scored on fewer tasks is
flagged so a single-task index isn't mistaken for a full one.

## Add results
```bash
pip install "glq[bench]"
export GLQ_BENCH_RESULTS_REPO=https://github.com/cnygaard/glq-benchmarks.git

# run + push records (captures provenance automatically)
glq-bench run --model <hf-id-or-dir> --tasks mmlu_pro,aime_2026,throughput --push
# the bf16 baseline of the same base is required for the % -of-bf16 index:
glq-bench run --model <base-bf16-id> --tasks mmlu_pro,aime_2026 --quant none --push

# regenerate the leaderboard + plots from all records
glq-bench leaderboard --out LEADERBOARD.md
glq-bench plot --kind all --out plots/
```

## Caveats
Numbers are reported **as measured in their run** — sample sizes (`n=30`/`n=60` for
AIME/MMLU-Pro single-sample) carry real noise; treat small per-task gaps as ties.
Each record's `config`/`extra`/`serving` fields carry the run details (thinking
budget, GPU, command). No claim is generalized beyond the run that produced it.
